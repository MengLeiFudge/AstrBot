# 棉花糖功能合集

作者：MengLei

## 插件用途

本插件是 AstrBot 当前固定功能入口，覆盖群务、菜单、生图、美图、表情管理、复读、养鲲、落樱之都、Arcaea、JM 漫画 PDF、Factorio 和异形工厂。本插件不拥有 Poke 逻辑：拍一拍不在这里生成特殊回复或专属文案，Poke 由 `astrbot_plugin_topic_concentration` 的拍一拍状态机处理，完整行为合同见 `../astrbot_plugin_topic_concentration/README.md`。

固定指令统一使用同一套触发规则：群聊和私聊都可触发；群聊可以 @ 当前 bot 后发送，也可以不 @ 直接发送；每个功能只把主指令展示在菜单里，别名只参与触发解析；指令不使用 `/` 这类特殊前缀，直接使用中文或英文字母。

普通聊天不在这里硬编码回复。明确呼叫、私聊或群聊激活窗口内的候选消息交给 AstrBot LLM 链路；未激活且未呼叫的普通群聊保持静默。

本插件发送菜单、生图、Lolicon、游戏面板、shapez、Arc 和自动表情等图片时，会从 32 条甜、俏皮、神秘和轻微功能相关短句组成的本地混合池随机选择 OneBot 图片 `summary`。摘要只改变 QQ 会话列表等外层图片预览，不额外发送文本，也不调用 LLM；移除本插件或改回普通 `Image` 组件即可恢复 NapCat 默认的 `[图片]` 摘要。

普通聊天使用原生生成、后处理分段与发送流程，默认关闭 `reply_style_guard_disable_astrbot_segmented_reply` 和长输入短回复阈值。插件不再限定两行/每行80字、按换行另拆短气泡，也不删除正文里的问句、后续解释、姐妹拒绝说明、Markdown或语气尾句。发送前仅保留内部提示泄漏、控制标记、权限提升建议和错误拦截；完整人设与说话风格沿用已有配置，防重复提示仍保留。首条等待只按原生分段后的第一段计算并抵扣已耗时，后续分段按原速度发送。

仍需分段的普通聊天结果通过公开事件发送 API 发送，首条只补等 `max(0, 原段间隔 - 本轮已经耗时)`；后续分段和研究补充按原间隔发送。已经由风格守卫改为 `GENERAL_RESULT` 的消息保持原来的直接发送。发送后还原已确认的消息链，再由框架调用原有 `after_message_sent`，保留表情清理和群聊激活；失败或取消不把原消息交回框架重复发送。此路径适用于本机 aiocqhttp 非流式文字配置，不替代启用后的原生语音转换。

群聊 LLM 最终返回以 `LLM 响应错误:` 开头的 AstrBot Core 内部错误结果时，本插件会先清空群结果，再由当前出错 bot 私聊固定主人 QQ `605738729`。通知只包含当前 bot QQ、来源群号、归一化错误类型和安全摘要，不携带群友原消息、prompt、上下文、凭据或上游原始错误正文；两只 bot 和所有群共用同一进程内的 600 秒冷却，同一归一化问题 10 分钟内只通知一次。私聊请求的失败结果不在此处改写；即使主人通知发送失败，群错误也不会恢复。这个发送守卫不新增 provider retry/fallback，也不改变 AstrBot Core 的 timeout 或重试参数。

本插件不再读取旧公开群上下文 JSON。群聊 LLM 上下文交给 AstrBot 当前会话上下文和本轮引用消息；`data\plugin_data\qqbot_features_runtime\ai\group_context\` 只作为历史快照清理对象。

群聊长输入短路只作用于群聊；私聊不受 `太长不看` 限制。私聊发送 OneBot 合并转发/折叠消息时，插件会通过 `get_forward_msg` 解包文字和第一层图片，再交给当前收到私聊的 bot 进入正常 AstrBot 会话与图片理解链路。

## 菜单指令

- `菜单` / `帮助` / `指令`
  - 发送统一图片菜单总览。
  - 展示当前分类：群务管理、棉花糖互动、养鲲、落樱之都、Arcaea、Factorio、异形工厂。
- `菜单<分类名>`
  - 发送指定分类详情图。
  - 示例：`菜单棉花糖互动`、`菜单Arcaea`、`菜单群务管理`。

## 功能目录（模型侧说明书）

- 每次 LLM 请求前常驻注入一份功能目录索引（约 500 字）：功能名 + 触发词/指令，模型因此始终知道 bot 有哪些能力。
- 当前消息命中功能别名时，追加该功能的指令原文与限制（最多 3 条、1800 字）；没命中只留索引，不追加详情。
- 数据源只有两处，不手写第二份：分类与别名来自 `menu_catalog.py` 的 `MENU_SECTIONS`，生图指令原文来自 `draw_catalog.py` 的 `DRAW_COMMAND_FACTS`。新增功能时改这两处，索引与详情自动跟上。
- 匹配是去空白后的子串命中，按别名长度和优先级排序；被更长别名覆盖的短别名（`生图` 之于 `生图模型`）会被丢弃，避免同一问题返回两份重复说明。
- 生图接口知识库仍按关键词单独注入，负责接口细节和“不得声称已开始绘图”这类行为约束；功能目录只负责“有哪些功能、确切怎么发”。
- 目录列出的都是已启用的能力，模型被问“能不能做、怎么用”时照实说明，不以“没有这个功能”拒接；分类名重复时以命令级条目为准，不再派生同名分类条目。
- JM 漫画条目直接给可发送原文（`jm<作品ID>`、好友限定、成品私聊发密码压缩包），与 `menu_catalog.py` 菜单图上的写法一致。

## 群务管理

- `清理群文件` / `群文件清理通知`
  - 作者或机器人自身限定。
  - 扫描超过一周的外层群文件并通知处理。
- 好友申请
  - 按配置自动同意 OneBot 好友申请。
- 群邀请与加群申请
  - 按配置自动同意 OneBot 邀请机器人入群和成员加群申请。
  - 机器人自身入群成功后优先私聊通知邀请者，文案包含群名和群号。
- 新成员入群欢迎
  - 云栖随机选择以“群地位”开头、表达群地位变量减 1 的完整表达式欢迎新成员。
  - 夜凛、星遥和月澄等已知机器人账号不会触发欢迎。

## 棉花糖互动

- 显式指令：`文生图 <提示词>` / `图生图 <提示词>` / `头像生图 <提示词>`
  - 两个标准动作分别只使用文字、使用单张原图；普通请求保留命令后提示词的内部空白和换行，不调用聊天模型改写；命中下述固定预设时改用预设原文。
  - 图生图优先使用同一条消息附带的图片，否则读取被引用消息中的图片；多张图、图片失效或缺图会在扣分前提示，不自动改用其他图片。
  - `头像生图 <提示词>` 使用发送者头像；`头像生图 @某人 <提示词>` 使用指定QQ的头像，包括机器人自己的头像。目标艾特须紧跟命令词，命令前的唤醒/回复艾特不作为目标，额外艾特会提示明确目标。
  - `生成豆豆眼头像` 固定使用发送者本人的头像，韩文 v1 和中文 v3 各生成两张，四个独立请求并行，等待全部结束后按 v1、v1、v3、v3 顺序发送全部成功成品。普通生图仍为一张。
  - 两版预设分别存于 `prompts/doudouyan-v1.txt`、`prompts/doudouyan-v3.txt`，保留完整原文；每次请求按 UTF-8 字节读取，不翻译、拼接、截断或修改空白。插件上传完整参考图，不执行自动裁剪。
  - 四张共用一次原图预加载及一次积分预扣；部分失败仍交付全部成功结果并说明缺失数量，不自动重生；全部失败才退回本次扣分。
  - 原有入口继续支持豆豆眼预设：`头像生图 豆豆眼`、附图/引用图后 `图生图 豆豆眼`、`生成我的头像的豆豆眼图片`；自然语言如“帮我把我的头像改成豆豆眼风格”“把这张图改成豆豆眼”在识别为实际改图请求并确定来源后，也使用同样的四张流程。附图优先引用，多图或目标歧义先提示，不扣积分。
  - 所有入口的开工提示显示“提示词来源：用户话语（无预设）”或“提示词来源：豆豆眼预设（完整固定原文）”；固定预设另列原图来源、两版各两张及一次扣分，资源读取失败不改用简短提示词。“无预设”表示未选固定模板，旧生成入口的条件改写仍保留。明确 `文生图` 始终走纯文字路径，旧 `生成` 引用纯文字消息时仍按普通请求处理。
  - 所有成品先逐张保存，再在一条引用消息中发送。全部未保存且发送失败才退积分；已有保存文件时告知可取回的文件名，不重复生成。
  - 所有入口的成品统一保存在插件运行数据根 `draw/outputs/YYYYMMDD/`，默认完整路径为 `data/plugin_data/qqbot_features_runtime/draw/outputs/`；文件名使用时间和唯一标识。
  - 动图版：把“生图”换成“生动图”，即 `文生动图` / `图生动图` / `头像生动图`，请求时带 `output_format: gif`。动图保留原始 GIF 字节、存成 `.gif` 并原样发送；上游可能回退成静态 PNG（实测 6 次里 1 次回退），回退时成品消息会注明“本次请求的是动图，但上游返回了静态图片”。实测动图为 9 帧、每帧 200ms、约 2048 像素、1.4–5.9 MB，尺寸和帧数由上游决定，`size` 参数会被忽略；豆豆眼预设是静态四张，`图生动图 豆豆眼` 会被拒绝。
- 自然语言入口（私聊，或群聊中明确 @ / 唤醒机器人）
  - 可说“画只猫”“来张星空图”“能帮我画只猫吗”；附图或引用图片后，可说“P一下这张，背景变蓝”“给她换件红衣服”。“帮我把我的头像改成水彩”使用自己的头像，目标头像须明确艾特且不能多选。
  - 请求完整时直接执行并按相同价格扣分，开工消息会回显提示词和来源；有歧义先提示补充，不扣积分。“再来一张”等依赖上次请求的表达需要重新写完整。
  - 只有当前正文明确要求时，引用文字才作为画面素材；询问能力、否定、评价旧图或单独发图不会自动生图。候选筛选可能漏判，可随时改用显式指令。
  - 说“画个动图”“来张 GIF”这类明确要求动画时，分类结果带 `gif: true`，按动图链路生成；上游回退成静态图时成品消息会注明。豆豆眼预设始终保持静态四张。
  - `draw_intent.py` 负责本地候选、单次当前 provider 分类和严格 JSON/来源校验，随后转换为标准指令组件复用下载、积分及交付；不建立第二条生图执行链或向量库。分类每用户最多一个并发、10 秒冷却、15 秒超时，引用读取最多 5 秒；限流或分类失败回普通聊天，明确指令不受分类冷却影响。
- 价格、模型与接口
  - 生图模型从 CPA `/v1/models` 返回的图片模型中自动选择，保存的模型已不可用时自动改用当前可用模型；每次用户请求按模型价格预扣积分（倍率 1000）：`gpt-image-2.6` 60 积分（0.06 元），`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst` 各 150 积分（0.15 元），未单独定价的模型按 0.06 元；普通生图一张，豆豆眼四张共扣一次。
  - 旧用户保存的模型已不在 CPA 注册列表时，下次生图自动改用当前可用模型并写回该用户记录，积分余额、群消息累计、排行和退款机制不变；生图命令不支持临时指定模型。
  - 提示词包含“仿照上面、这张图、参考、聊天记录”等上下文指代，或引用了图片时，会先用当前会话 AstrBot provider 整理成准确生图提示词，再扣积分调用生图。
  - 如果只有 `[图片]` 这类占位、没有可用引用图片 URL/路径或引用文本，插件会直接提示补充引用或写完整提示词，不扣积分。
  - 插件配置 `base_url` 默认是本机 CPA `http://127.0.0.1:8317/v1`，`api_key` 填 CPA 客户端凭据；渠道选择与优先级由 CPA 管理。插件按模型名识别图片模型（含 image、imagen、dall-e、flux、banana 等关键字），版本从新到旧、基础名优先于变体；请求返回“模型未注册为图片模型”时丢弃缓存重新读取并逐个改用其他可用模型。HC/RC 渠道中这些模型记录必须设置 `image: true`，否则 CPA 会在本机直接返回 HTTP 400。
  - 文生图走 `/images/generations`；参考图走 `/images/edits` multipart 上传，单张最多 20 MiB，GIF 等格式取首帧转换为 PNG。
  - 出图尺寸由请求的 `size` 决定，渠道按原尺寸返回。只认一种写法：`<生><画幅>图<档位> 提示词`。档位紧跟指令，`1k` `1024x1024`、`2k` `2048x2048`、`4k` `4096x4096`，默认 `4k`，如 `文生图1k 一只白猫`、`图生图2k 换成水彩`。
  - 画幅插在“生”和“图”中间，只有 `横` / `竖` / `动` 三个选择：`文生竖图2k 一只白猫`、`图生横图4k 换成水彩`、`文生动图 提示词`。竖幅 1k `1024x1536`、2k `1152x2048`、4k `2304x4096`；横幅 1k `1536x1024`、2k `2048x1152`、4k `4096x2304`；动图不走横竖尺寸。画幅词写到别处（如 `文生图2k 竖图`）会直接报错并给正确写法。
  - 档位后面要空一格再写提示词；写成 `文生图4k一只猫` 会直接提示正确写法，而 `文生图 4k显示器`（前面有空格）仍按提示词处理。默认档位的三个尺寸由配置 `draw_image_size_square` / `draw_image_size_portrait` / `draw_image_size_landscape` 控制，豆豆眼四张并行同样走这些档位（默认 4K）。
  - 实测（同一提示词）：4K 单张 73 秒；2 张并发 70–72 秒；3 张并发 72–73 秒且有一次上游 502；4 张并发 67–76 秒全部成功；2K 单张 39 秒。渠道对同时请求基本并行处理，单张耗时不受并发拖慢；失败是上游偶发，不是排队。`auto` 返回 `1024x1536` 竖图，因此不作为默认。
  - 生图成功、失败或超时失败都会引用原始生图请求；生成默认 240 秒总超时，全部生成失败后退回本次扣除的积分。原图准备最多 30 秒，结果发送最多 60 秒；URL 和 Base64 返回均校验为有效图片；PNG保留原字节，其他格式转PNG并保留实际尺寸，再统一保存与交付，结果及转换后均限制32 MiB。
  - 不再支持 `生成`、`棉花糖生图`、`棉花生图` 前缀：群里不 @ 的“生成一只白猫”不会触发，请用显式指令，或在私聊 / @机器人 时说“生成一只白猫”，由 AI 判定后调用同一条生图链路。显式指令后只有空白时固定回复补充提示词，不扣积分。
- 生图接口知识库
  - 用户询问模型、价格、画图接口、`body`、`size` 或 Images 路径时，会在 LLM 请求前注入当前功能说明。
  - 如果用户引用上一条问题后只说“回答一下”，被引用消息参与知识库判定和 LLM 上下文。
  - 当前请求直接等待图片，不使用 `async=true` 和任务轮询；只有接口问题才解释 CPA 接入细节。
- `生图模型` / `生图价格`
  - 展示当前模型、CPA 当前可用的生图模型列表、各模型人民币价格及对应积分消耗；保存的模型已不可用时提示下次生图会自动改用可用模型。
- 旧模型切换指令
  - `切换生图模型 <模型名>` 和 `生图模型 <模型名>` 保留解析，只接受 CPA 当前注册的模型名；菜单不再展示切换指令，但功能目录会告诉模型这条指令可用，用户问“怎么切换模型”时直接给出指令原文。
  - 模型名不在注册列表时返回当前可用模型及普通生图用法，不改变积分。
- `查看积分` / `balance` / `points`
  - 查询当前 QQ 的积分、当前模型和该模型单次积分消耗，不展示历史累计消息数。
  - 回复末尾提示 `生图模型`，不再提示切换。
- `积分排行` / `积分排行榜`
  - 按跨群累计积分输出全部用户中积分最高的前 10 名；同分时按 QQ 号稳定排序。
  - 每条群消息缓存当前群的群名片、QQ 昵称和时间；排行优先用当前群群名片、其次当前群 QQ 昵称，当前群没有时只使用其他群最新 QQ 昵称。
  - 仍没有昵称时显示中间位星号脱敏的 QQ，不使用其他群群名片。
- `用量`
  - 发送两张图片：第一张按账号依次展示 5h / 7d 额度卡和该账号自己的当前 7d 周期用户消费榜，全部账号区块结束后展示全账号当日 / 本周 / 30d 消费榜；第二张展示 CodexRadar 社区公开的智力效率榜，包括各模型档位的 IQ、平均费用、平均耗时和近 24 小时有效作答数。
  - 每个账号榜的窗口起点为该账号原始 `seven_day.resets_at - 7 days`，按稳定 `account_id` 过滤：起点当天向下取整到所在小时后汇总小时趋势（例如 09:10 从 09:00 桶开始），后续日期按自然日汇总 `actual_cost`；不同账号不再合计，每个榜显示该账号全部非零用户并按金额降序。底部全账号榜使用 Sub2API `actual_cost` 和固定 `Asia/Shanghai` 时区：当日 / 本周 / 30d 以同一次后台刷新时刻为终点；当日起点为最近已到达的 08:00（08:00 前回退到前一天 08:00），本周起点为最近已到达的周一 08:00（周一 08:00 前回退到上周一 08:00），30d 起点等于当日起点再减 30 个日历日；起点当天从该整点小时桶开始汇总小时趋势并包含当前小时桶，后续日期按自然日汇总。

- `reply_style_guard_long_input_tldr_threshold_chars`
  - 默认0，关闭长输入短回复，长消息正常进入模型。非零值仅用于明确选择的群聊短回复策略，不应为了节约 token 或提速开启。

  - 默认 `太长不看喵`。
- `jmcomic_enabled`
  - 默认开启。关闭后 `JM作品ID` 命令不执行下载。

- `jmcomic_cache_max_gb`
  - 默认 10 GiB，范围 1-100 GiB；超限按 `metadata.json` 的最后访问时间淘汰。
- `source_knowledge_max_results` / `source_knowledge_max_chars`
  - 默认 `4` / `2600`。源码知识按低成本运行，需要追查大文件或更完整源码证据时再临时调高。
- `meme_manager_auto_collect_enabled`
  - 默认开启，后台把群聊里出现的新图读一遍再决定收不收：可爱软萌是加分项而不是唯一标准，有棗、表达清楚、画质干净的图都可以收；擦边、脱衣或暴露梗、恐怖血腥、真人照片、截图、广告和模糊低清的图不收藏。
- `meme_manager_auto_collect_interval_seconds` / `meme_manager_auto_collect_max_images`
  - 默认最短分析间隔 60 秒；`max_images` 是图库总量硬上限，默认 400 张，只作兵底，日常由分类配额控制。最短间隔不能低于 5 秒。
- `meme_manager_meme_entry_min_score`
  - 默认 55（满分 100）；新图四项分合计达到该分数才可能入库，低于它直接丢掉。分类满额后还要和现有图比排名，分类里还有没打完分的图时先收下，等打分批次统一裁。
- `meme_manager_curate_enabled` / `meme_manager_curate_interval_minutes` / `meme_manager_curate_batch_size`
  - 默认开启，每 15 分钟最多读图 60 张，按“从没打过分 → 分数过期”顺序消化；没有待打分的图时空转不读图。分类超过配额时把排名最低的移入 `archive` 对应分类，一张不删。
- 分类配额写在 `meme_manager/library_plan.py` 的 `CATEGORY_QUOTAS`：主力情绪 20 张、一般 12 张、冷门 6 张，共 27 类 390 张。同文件的 `CATEGORY_MERGES` 决定旧分类怎么合并；`CATEGORY_ARCHIVE_ALL` 里的退休分类不再整类归档，图统一并进 `see`，交给配额和打分决定去留。
- 评分维度：萌度 0-40、表达力 0-25、画质 0-20、群聊可用 0-15；可用分为 0 的图按原因分流：色情暧昧迁入私密分类，风控不合格（恐怖血腥、真人、截图、广告、水印、认不出）进审核队列，重复的直接删，剩下画质低和分类不合适按低分归档。排序分 = 总分 + 新鲜加成（入库当天 15 分，每天减 0.5，30 天后归零）；审核页把两部分分开显示成「91 +10」，鼠标悬停可看排名，分类内按排名排序。分类满了再收新图时，分差超过 5 分直接换，5 分以内才让模型看最低 2 张加新图挑。配额是硬上限：每轮打分开始前先跑一次 `enforce_quotas()`，把所有超额的分类按分数从低到高裁到配额，再跑 `rebalance_quotas()` 把归档里分数比库内最低分高的图换回来，两个都是纯规则不需要模型；只有“没打分的图数量超过要裁的张数”时才跳过该分类，避免误删还没评过分的好图。
- 描述（caption）在模型认得出图里角色时以角色名开头，用通用中文译名（如初音未来、蕾姆、芙宁娜），后面接动作和情绪；认不出或不确定就不写名字，不猜。描述限 40 字。
- 可用分为 0 的判定只看下面这份清单，清单外的东西不扣分；土味、尴尬、阴阳怪气、画风偏好这类口味问题都不算理由。
  1. 露点或裸露。
  2. 性行为暗示。
  3. 脱衣、内衣或暴露梗。
  4. 恐怖血腥。
  5. 真人照片（含真人 cos）。
  6. 聊天、评论或工作界面截图（包括仿聊天气泡）。
  7. 个人资料、联系方式、证件或二维码。
  8. 广告、引流、下载推广。
  9. 水印或平台标识盖住主体。
  10. 看不出情绪、糊到认不出内容。
  清单外的情况按萌度、表达力、画质正常给分；光腿、短裙、赤脚、躺姿、伸手这类正常可爱插画不归档。
- 每条归档记录都带具体原因 `rule`（上表十项加画质低、分类不合适、重复），审核时能直接看到命中了哪一条，不再只写笼统的 unfit。
- 偏暧昧或色情的图（前三条规则）不删也不丢分销毁，按程度迁入三个私密分类：`private_flirt`（暧昧调情）、`private_intimate`（亲密接触）、`private_explicit`（露点裸露）。三者都是普通分类、各自配额 20 张，超了就按排名归入 `archive`；区别是 `auto_send_enabled=false` 且 `audience=owner_only`，云栖不往群里自动发，只在跟主人聊天时可用。
- 新图入库前先查重：内容 sha256 相同的直接跳过；感知哈希（dHash）汉明距离 6 以内的当作同一张图（能拓 QQ 重压缩）；同分类描述相似度 0.7 以上的当作同款，只保留分高的那张。
- `meme_manager_send_check_enabled` / `meme_manager_send_check_timeout_seconds`
  - 默认开启，选中表情后必须由图片模型实际读图确认才发送，不依赖图库标题或描述；读图超时或未通过则本次不发该表情，并把该图标记为停用。
