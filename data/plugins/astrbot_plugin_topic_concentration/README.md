# 棉花糖群聊激活

作者：MengLei

## 插件用途

本插件负责云栖单账号的普通 LLM 路由、命名呼叫判定，以及按群保存的短时激活状态。直接对话按请求选择回复模型；不切换会话默认模型或人格，也不实现跨账号 worker 调度。消息与媒体遵守根工作区的 [消息完整性与按需触发](../../../../docs/message-context.md)。

## 核心行为

- 已知姐妹机器人发来的普通消息和拍一拍在最高优先级入口终止，覆盖私聊与群聊；同时关闭该事件的默认 LLM 请求，避免跳过插件后仍由框架继续回复。
- 直接 @ 或引用云栖、明确命名呼叫、仅 @ 云栖以及私聊会进入普通 LLM 链路。
- 多个具体账号同时 @ 且包含云栖时，通过插件的 `on_waiting_llm_request` 钩子，在原生请求构造前按结构化消息顺序恢复全部账号 mention。单独 @、`@全体成员` 和命令路由保持框架原逻辑，不修改 Core。
- 云栖、夜凛、星遥和月澄都属于棉花糖家族，但命名呼叫必须使用具体名字。本插件只识别“云栖”；“棉花糖”“萌萌棉花糖”和 `qqbot` 不作为个人呼叫别名，只叫其他姐妹也不会唤醒云栖。
- “云栖”“云栖，帮我看看”等明确呼叫可直接唤醒；只是谈论云栖时继续判断呼叫意图。家族称呼不是禁词，例如“云栖，棉花糖好吃吗”仍是对云栖的有效呼叫。
- 群聊显式呼叫会激活当前群 10 分钟（`logic.py` 的 `ACTIVATION_WINDOW_SECONDS = 600`）。激活窗口内的普通消息成为候选，由模型通过 `[[QQBOT_SKIP_REPLY]]` 决定静默，或通过 `[[QQBOT_DEACTIVATE]]` 结束激活。
- 控制标记兼容开头 `Q` 被 Unicode 替换字符损坏的输出；发送与历史清理使用同一解析规则。每次请求前清除 assistant 历史中的这些标记，保留正常文本、用户消息和工具调用，避免异常标记继续影响模型或错误续期。
- 普通群消息沿用激活与呼叫策略决定何时触发，纯图片和混合文字图片完整进入原生视觉链。原有会话历史保留，不在每轮请求中额外强制补读30条QQ记录；上文不足时由模型按需使用历史工具。
- 请求提供 `read_chat_history` 工具，默认每页 30 条，`count` 可取 1–100；使用返回的 `next_before_message_id` 继续向前查阅。群/私聊目标固定为实际事件，翻页游标必须属于同一会话；原图作为工具媒体返回。`provider_ltm_settings.image_caption=false` 只关闭额外的被动背景描述，主模型读图能力继续启用。
- 可在同一 provider source 下配置 `deepseek-responses/deepseek-flash-reply`，发给 CPA 的模型为 `qqbot-deepseek-flash`，自定义请求体为 `{"reasoning":{"effort":"high"},"max_output_tokens":8192}`。私聊或非拍一拍的显式呼叫仅在会话使用上述默认模型、且事件没有指定其他 provider 时选择该回复模型；未配置则沿用原模型。候选、拍一拍、命名意图判断、空回复纠错和上下文压缩继续使用默认模型，同样使用 high 思考。
- 8192 是单次推理与正文共享的最大输出预算，source 请求超时为 120 秒；high 思考保留推理能力，实际耗时和输出用量按请求记录观察。原生主对话中的必要工具调用沿用原链路，不新增独立规划或自审循环。
- 非拍一拍显式呼叫必须产生可见回复；无工具调用的最终结果为空或只有控制标记时，使用当前 provider/model 纠错重试一次。正在调用工具的中间响应继续研究，不触发空回复重试。
- 候选进入队列时记录激活代际和时间。等待超过 30 秒、激活过期或代际变化时静默丢弃；旧响应不能覆盖后续显式激活或反激活。
- 新的私聊或显式文字呼叫通过公开 `event.stop_event()` 停止同会话旧拍一拍、候选请求，释放拍一拍 AI 租约；直接呼叫处理期间不加入新的可选请求。不打断先前的直接对话。
- 普通对话可以先发有用且可靠的公开阶段结论，再继续研究。部署配置 `provider_settings.buffer_intermediate_messages=false`，保留 `display_reasoning_text=false`。本轮起点记录在事件中，功能合集插件只从首条分段等待扣除已处理时间；后续分段和研究补充保持配置速度。
- 固定命令、生图、菜单、群务、下载和游戏入口由 `astrbot_plugin_qqbot_features` 直接执行，不进入普通 LLM 候选链路。
- 夜凛、星遥和月澄只作为静态姐妹关系与机器人防回环账号，不是 AstrBot worker。

## 拍一拍状态机

- 状态按 `group_id + self_id` 存在内存中，插件重载即清空；60 秒滚动窗口内不按发送者拆分计数。
- 1-2 次为 CALM、3-5 次为 ANNOYED、6-8 次为 ARMED，第 9 次起进入 30 秒 MUTE。内部等级和计数不得暴露给模型或群友。
- 非 MUTE 状态同一群同时只允许一个 Poke 进入 AI，释放后有 3 秒冷却；被节流的拍击仍计数。
- 模型先根据人格、上下文和当前情绪在无视、反拍、文字三种反应中选一种，没有固定概率或轮换。无视只返回内部跳过标记；反拍调用请求级 `qqbot_poke_back` 后以跳过标记结束，不追加文字；只有选文字才要求自然可见回复。重复拍击没有新内容时倾向无视或反拍，不必每次编一句新话。ARMED 额外提供请求级 `qqbot_enable_poke_mute`。
- 通用文字风格、避免重复和普通显式文字呼叫的必答提示不覆盖拍一拍选择。文字分支仍须针对当前拍击自然接话，避免固定句式、单个标点或占位符。
- 两个工具的目标固定为当前拍击者，不接受目标参数；同一事件的副作用只尝试一次。提前禁言成功才进入成功冷却，失败或取消会释放 claim。
- MUTE 期间不调用 AI，本地通过 OneBot 禁言当前拍击者 30-90 秒。只有实际发送可见文字才激活群聊；静默、反拍和禁言都不激活。
- 每次进入 MUTE 都递增状态代际，使旧 Poke 响应和旧请求级工具失效。

## 数据边界

插件只维护群激活、候选代际、拍一拍计数、AI 租约、请求级工具 claim、禁言冷却、MUTE 窗口和当前请求的弱引用等内存状态，不写入数据库，不读取其他账号运行态，也不实现独立 provider fallback。
