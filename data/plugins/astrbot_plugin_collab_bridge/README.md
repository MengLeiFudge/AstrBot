## 配置

在插件配置中填写 bridge_id、database_id、generation、task_id、platform_id、token，与 Pi collab 数据目录中的 bridge.json 一致；默认端口 19191。provider_id 指定单次无工具汇总模型，默认示例 deepseek-responses/deepseek-flash，应核对实际模型。真实 token 不进 Git、不交给模型。

完整迁移、配置、接口与 Pi 操作见 pi-collab 的 docs/bridge.md。Pi 端需要 schema 2，显式备份迁移后重新加载扩展。未配置时插件记录未配置状态，不收集消息、不主动调用模型。

运行数据由 get_astrbot_plugin_data_path() 定位到 plugin_data/astrbot_plugin_collab_bridge/queue.sqlite3。插件配置由 AstrBot 管理，源码目录不存运行数据。改绑定或世代时先归档旧队列，再重新配置；不能把旧消息自动改投新房间。

## 行为

- 群消息直接 @云栖 且包含正文文本即静默入队，无需“需求”前缀；只复制当前消息的直接文本，不展开图片、引用或转发内容。没有正文的 @ 不入队。
- 收集不调用模型、不回复、不终止事件，正常聊天和 draw_intent 等原有处理照常运行；满队列或写入失败只记日志，不向群发送收件结果。私聊只处理主人确认，不作为汇总素材。
- 每群默认 10 条或 30 分钟攒一批。先核对本机服务鉴权与绑定再调用一次 llm_generate(tools=None)。所有群合计每天 UTC 最多 24 次模型尝试，失败也计数。
- 原文、批次 ID、预算先持久化；摘要生成后再持久化，HTTP 失败复用原包重试。模型失败的批次至少等待 30 分钟再试。
- 汇总提炼项目/Pi需求、问题和分歧，保留来源消息 ID，忽略闲聊、问候和画图、查询等日常指令。固定空结果 NO_REQUIREMENTS 在本地标记已处理，不发帖、不唤醒 Pi；该次尝试仍计入预算，原文按七天规则清理。模型意图筛选可能漏判或误判，摘要始终只是素材。
- 原文最多七天，默认容量 16 MiB/10000 条；到期记录告警并停止发布该过期批次。原文被 Pi 确认接收后可提前清理；摘要保留。
- Pi 显式选择的一句结论回来源群；待决卡片只私聊主人。确认必须是主人本人的私聊“确认 <决策ID> <选项>”，群消息与模型文本不能批准执行。
- 已发送的回传 ID 本地落盘后再 ack，仍存在 QQ 发送成功但本地落盘前崩溃的重复窗口，输出附稳定协作 ID。
- 没有 Pi 会话时不汇总；后台只重试本机服务。首次成功处理与从暂停恢复时记录 info，暂停记录 warning 和错误类型；同一持续故障不重复刷日志，不记录 token、请求体或模型内容。停用/重载插件取消循环并关闭连接，不结束 Pi。

## 生效与验证

代码检查使用 Python 静态语法与类型检查，不通过发送 QQ 消息或调用模型验收。部署后按 qqbot 根目录的既有启动入口重启生效。插件自动生成的配置和 plugin_data 不提交 Git。
